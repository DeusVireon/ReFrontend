颜色管理：请查看 global.css 获取我们目前已有的色板，
如果没有很充分的理由，不允许新增色板，因为这会使颜色变得杂乱（尤其是部分 AI 喜欢用不同强调色绘制数据卡片）

样式管理：要求很简单，如果你使用 vibe coding，请确保每一个 tailwindcss 标签都是必要的

依赖管理：如果没有很充分的理由，不允许引入依赖。如果要引入新的依赖，建议先进行讨论。
如果你使用 vibe coding，请告诉 AI 这个限制，早期前端开发者信奉“永远别造轮子”导致某些 AI 学会频繁引入偏门的依赖，这不是一个好习惯。
目前关键依赖：
react-gauge-component 用于绘制仪表盘，你可以在 `https://antoniolago.github.io/react-gauge-component/` 进行预览
rechart 应该满足所有图表的绘制，即使是复合图表也很方便，不建议为了某种奇怪的图表引入依赖，优先使用 rechart 解决
r3f 主要是 Dashboard 的 3D 渲染，和 DataAnalyze 应该没什么关系
zustand 状态管理库，这个库很常用，如果你没见过，请先大致的学习一下
tailwindcss 提供样式标签，既然有此库，就不应该再编写 css 文件，动画请安插到 global.css 中（已有示例）
lucide-react 提供图标，不建议再引入第二个图标库
如果真的有必要，Framer-motion 可以选择添加而不需要讨论，因为此库足够主流且覆盖未满足的需求，不过目前没有使用
如果有更好的替代品，请提出来

请在 dev-pDataAnalyze 分支上工作，而不是直接提交到 main，否则你的每个 commit 可能都需要进行冲突处理
如果你有临时提交，应该进行简单标记，并在在下一次完整提交时使用“提交（修改）”操作，并同步更新 commit message

所有列表型组件应该配置好 map 展开而不是重复多个标签
